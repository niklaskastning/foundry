# Foundry im Vergleich zu Warp

Stand: 5. November 2026. Diese angeforderte Produktbewertung trennt **Funktionen** und **UI**. Die verbindliche Reihenfolge und Abnahme bleiben im [Umsetzungsplan](implementation-plan.md#nächste-produktlieferungen); dies ist keine zweite Roadmap. Ziel ist eine nutzbare Software Factory mit T3 als interaktivem Arbeitsplatz. Ein vollständiger Nachbau von Warp Terminal ist dafür keine Voraussetzung.

## Grundlage und Aussagegrenzen

Geprüfter Code: `1d057f8c0dfb58d4c147e3be54cb09200645cf54`. Browser-Rundgang auf dem Entwicklungs-VPS: Main `e039785487fd3b406914e6e13d98b67c83f80d04`, Image `sha256:27b4bab343a692986a33966b5b4666a0ed7bed74c3c7e98dfd0f97a7d1cff8ab`, Readiness erfolgreich. Der Checkout enthält dessen Merge; die verglichenen Produktdateien haben denselben Stand.

Auf ausdrücklichen Wunsch direkt über VPS-Loopback geprüft, ohne Cloudflare-Änderung oder Service-Restart. Ein temporärer lokaler Prüfproxy stellte eine kurzlebige Foundry-Sitzung und lesende T3-Autorisierung bereit, passte die Descriptor-Origin an und erlaubte Loopback im ausgelieferten Client-Transport. Das ist **kein Nachweis des regulären Login-/HTTPS-Flows**. Die Geschäftsansichten und Daten kamen aus dem laufenden Main. Keine Aufträge gestartet, Trigger aktiviert oder bezahlten Provider-Turns ausgeführt. Schreibaktionen und Worker-Bindings waren mit diesem Lesezugang teilweise gesperrt; diese Anzeigen belegen keinen Worker-Ausfall.

Im Browser geöffnet: normaler Thread, Instanzeinstieg, Verbindungseinstellungen, Factory-Liste, Git-Definition, bestehender Auftrag, erfolgreicher vierstufiger Run mit Attempts und Handoff-Auswahl, GitHub-Trigger und globale Inbox. Die Inbox war im offenen Filter leer; Antworten/Freigaben wurden im Code geprüft, nicht erneut ausgeführt. Windows, Offline-Recovery, Terminalausführung und echte Handoff-Mutationen wurden in diesem Rundgang nicht abgenommen.

Warp: öffentliche Website und Dokumentationsseiten einschließlich eingebetteter Produktbilder im Browser gelesen. Kein angemeldeter Warp-Account und kein eigener Warp-Run. Die Homepage unterscheidet Factories, Terminal und Agent CLI und bewirbt Factories weiterhin mit Early Access; die folgenden Angaben sind dokumentierte Fähigkeiten, keine selbst geprüften Leistungszusagen. Beim anschließenden Abgleich mit `main` (`b432d5287`, PR #61) wurde der inzwischen implementierte Factory-begrenzte Maschinen-Lesezugang ergänzt. Der oben dokumentierte Browserstand bleibt unverändert; daraus folgt keine neue öffentliche Access-/CI-Abnahme.

## Empfohlener Fix und Abgleich zum Plan

**Nächste große Lieferung: wiederverwendbare Factory-Agenten in einem zusammenhängenden Arbeitsplatz.** P28/P52a liefern die Funktion, P49b erschließt sie im Produkt. Ein reiner Navigationsumbau würde die fehlende Ausführungsfähigkeit nicht beheben; neue Backend-Ressourcen ohne bedienbaren Weg würden den bisherigen Verwaltungscharakter fortsetzen.

Der Schnitt erweitert die kanonische Git-Definition um Rollen und Skills, löst unterstützte Einstellungen pro Step auf und hält deren Version am Run fest. Die UI zeigt diesen Stand, startet einen Auftrag mit geprüften Defaults und führt über Run/Inbox/T3 zum selben Auftrag zurück. Zunächst bleiben die tatsächlich unterstützten Codex-Fähigkeiten maßgeblich. Weitere Harnesses erhalten eigene Adapterabnahmen, statt durch einen Dropdown vorgetäuscht zu werden. Die detaillierten Abnahmekriterien stehen ausschließlich im Umsetzungsplan.

Die Planbereinigung entfernt den bereits erledigten P17-/MVP-Pfad aus der Zukunftsreihenfolge, kennzeichnet P49 als gelieferten Basisschnitt mit offenem Ausbau und trennt G12 vom optionalen Koordinator. Parallelität wird mit realer Worker-Kapazität gekoppelt. Sandboxes rücken vor die vollständige Qualitäts- und Self-improvement-Ausbaustufe; P54a kann schon vorher deren Messgrundlage legen. Native Anmeldung bleibt ein eigener großer Produktpfad, aber keine Voraussetzung, um im vorhandenen Access-Modus Rollen und Ausführung auszubauen. Zusätzliche Connectoren, kosmetische Anpassungen und Terminal-Parität folgen dem konkreten Bedarf.
